# Управление IT-фирмой: доработка для компании «Ваш компьютерный мастер»

Дипломный проект по программе «1С-программист: с нуля до middle» (Баст К.С.).  
Все заявленные работы выполнены.

## О проекте

В конфигурацию «Управление IT-фирмой» добавлен новый функциональный блок: подсистемы «Работа с заявками клиентов» и «Расчёт управленческой зарплаты». Реализованы отчёты, инструкция по начальной настройке и автотесты для подсистемы «Работа с заявками клиентов». Результат размещён в репозитории GitHub.

Полное техническое задание: [ссылка / приложение].

## Цель и задачи

Спроектировать, внедрить и подготовить к использованию новый функциональный блок в конфигурации «Управление IT-фирмой». Для этого требовалось:

- создать подсистемы «Работа с заявками клиентов» и «Расчёт управленческой зарплаты» под процессы заказчика;
- разработать отчётность по новым объектам;
- подготовить инструкцию по первоначальной настройке;
- сделать автотест для проверки подсистемы «Работа с заявками клиентов»;
- разместить результат в новом репозитории GitHub.

## Реализованный функционал

### 1. Подсистема «Обслуживание клиентов»

#### Документ «Обслуживание клиентов»

Сценарий заявки: клиент сообщает менеджеру проблему; менеджер находит свободное время и планирует работу специалиста. После планирования Telegram-бот уведомляет специалистов. Специалист выполняет работы в офисе клиента или удалённо. По завершении он получает подписанный лист учёта рабочего времени либо его скан/фото. В листе указаны виды работ и часы к оплате; этот документ подтверждает выполнение работ. Затем специалист вносит в систему виды работ, фактически затраченные часы, часы к оплате и прикрепляет скан/фото листа учёта.

Документ заполняют специалисты и менеджеры. Для них созданы профили `BKM_Специалист` и `BKM_Менеджер по обслуживанию`.

#### Документ «Реализация товаров и услуг»

В документ добавлен выбор договора с видом «абонентская плата». Он может автоматически заполняться суммой ежемесячной абонентской платы и суммой работ, выполненных за месяц по документам «Обслуживание клиентов». Из документа печатается акт об оказанных услугах. Документ использует бухгалтер; для него создан профиль `BKM_Бухгалтер`.

#### Обработка «Массовое создание документов Реализация товаров и услуг»

В начале месяца бухгалтер пакетно формирует акты по всем абонентским договорам. Для обработки создана роль `BKM_ИспользованиеобработкиМассовоеСозданиеАктов`; она подключена к профилю `BKM_Бухгалтер`.

### 2. Подсистема «Расчёт управленческой зарплаты»

В фирме есть специалисты и административный персонал. Специалисты получают минимальный оклад и процент за выполненные работы клиентам; административный персонал — оклад. Руководство может назначить сотруднику разовую фиксированную премию. Из дохода удерживается НДФЛ 13%.

Зарплата рассчитывается документами «Начисление заработной платы» и «Начисление фиксированной премии». Для отпусков используется «Планирование отпусков»: график составляется в начале года.

Чтобы видеть пересечения отпусков, предусмотрена кнопка «Анализ графика». Она открывает форму с диаграммой Ганта по каждому сотруднику.

Для подсистемы создан профиль `BKM_Кадровик-расчетчик`.

### 3. Отчёты

- **«Выработка специалистов»** — по выбранному специалисту и периоду показывает отработанные часы и сумму процента от выплат клиентов.
- **«Анализ выставленных актов»** — выводит клиентов, договоры и суммы, которые нужно выставить по документам «Обслуживание».
- **«Расчеты с сотрудниками»** — показывает начисления и выплаты каждому сотруднику за период, а также задолженность на начало и конец периода.
- **«Расход запланированных отпусков»** — за выбранный год сравнивает плановые дни отпуска и фактические дни нахождения сотрудника в отпуске.

### 4. Подсистема «ДобавленныеОбъекты»

В неё входят все объекты, добавленные при доработке. Подсистема доступна только администратору.

## Инструкция по начальной настройке и эксплуатации

При первом запуске дополнительный функционал настраивается в режиме 1С:Предприятие.

### Создание пользователей

1. Создайте пользователя с профилем «Администратор».
2. Создайте пользователей с профилями `BKM_Бухгалтер`, `BKM_Кадровик-расчетчик`, `BKM_Специалист` и `BKM_Менеджер по обслуживанию`.

### Подсистема «Обслуживание клиентов»

- Под администратором настройте Telegram-бота.
- Настройте регламентное задание для отправки сообщений боту.
- Из параметров Telegram-бота заполните константы `BKM_ТокенУправленияТБотом` и `BKM_ИдентификаторГруппыОповещения`.
- Создайте или выберите номенклатуру с видом «Услуги» для актов. Рекомендуются «Абонентская плата» и «Работы специалиста». Запишите их в константы `BKM_НоменклатураАбонентскаяПлата` и `BKM_НоменклатураРаботыСпециалиста`.
- До первого использования подсистемы кадровик-расчетчик должен заполнить справочник `BKM_Сотрудники`: внести фамилии сотрудников и указать в регистре сведений `УсловияОплатыСотрудников` процент от выполненных работ. Сведения о графике и окладе можно заполнить позже.

### Перед первым использованием подсистемы «Расчет зарплаты»

- Заполните справочник «Графики работ» (например, пятидневка, шестидневка). Для отпуска есть предопределённая запись «Отпуск календарные дни».
- Обработкой «Заполнение графиков работ» заполните график. В поле «Выходные дни» укажите номера выходных дней недели подряд без пробелов. Например, для пятидневки — `6,7`.
- Кадровик-расчетчик должен дополнить регистр сведений `УсловияОплатыСотрудников` данными о графике работы и окладе.
- В разделе «Сервис» назначьте график для отпуска; при этом должны учитываться все дни.

## Тестирование

### Сценарии

- планирование двух обслуживаний на специалистов от имени менеджера;
- закрытие обслуживаний от имени специалиста;
- массовое создание актов от имени бухгалтера;
- формирование отчёта «Анализ выставленных актов».

### Автотесты

Автотесты реализованы в Vanessa Automation.

### Порядок запуска

Тесты идут строго по порядку, так как часть из них опирается на данные, созданные предыдущими:

1. Создание_документов_Обслуживание_клиента.feature;
2. Закрытие_документа_Обслуживание_клиента_специалистом.feature;
3. Массовое_создание_актов.feature;
4. Отчет_анализ_выставленных_актов.feature.

### Условия прохождения

- Тесты запускаются на приложенной базе, где настроены предопределённые данные и заполнены справочники.
- Перед запуском клиент-тест должен быть закрыт.
- После прохождения пакета тесты можно запускать повторно в любом порядке.
